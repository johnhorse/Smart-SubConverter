## Problem Statement

自建订阅转换生态里，后端和规则库都很强（subconverter 内核什么格式都能转、ACL4SSR 持续维护），但「懒人友好」这一层是断的：

- subweb（Vue 2 时代）和 CareyWang/subconverter-front-end 都把 subconverter 的十几个参数字段原样端给用户，小白劝退；
- Sub-Store 页面现代但定位是玩机党的「订阅管理器」，面板里文件/脚本/同步/覆写一堆概念。

目标场景（剧本 A · 朋友自助式）：部署者一条 docker 命令起服务，小白朋友打开页面 → 粘贴自己的订阅链接 → 点一下 → 拿到能直接用的转换订阅链接，全程不需要理解 target、远程配置、编码这类术语。

## What Makes This Cool

用户原话：「真·零选项模式：链接甩给朋友，他点一下就能用」。

定位一句话（也是 codex 识别出的兴奋点）：**「Sub-Store 是给玩机党的，我这个是甩给小白的一键贴纸」**——漂亮页面是载体，免解释才是产品价值。

技术上的爽点：这是个「壳工程」而非「内核工程」。subconverter 内核是 C++，fork 它等于背永久维护债；而 Aethersailor/SubConverter-Extended（基于 asdlokj1qpi233/subconverter 深度演进）恰好是为「部署即忘」而生的底座。我们仓库零 C++，全部精力花在朋友看到的那一层。

## Constraints

- 客户端**候选集**（非承诺）：Extended 实际暴露的 target × 线框图 chips 的交集（Clash/Mihomo 系、Surge、Quantumult X、Loon、Stash、Shadowrocket、sing-box、v2ray 系等）。V1 只承诺兼容矩阵中**实测通过**的「客户端 × 协议 × 模板」组合（与前提 4 同口径），未测组合一律标注「未验证」
- 部署者零维护：不维护规则副本、不重拉镜像也能保持新鲜
- 部署门槛：V1 = 局域网开箱，单条 docker 命令、零反代知识；公网 HTTPS 为 V1 非目标（README 附录给非官方 Caddy 反代示例 + 强制 token 说明）
- 开源项目形态，社区可贡献

## Premises

六条终版前提（含 codex 修订，全部经用户确认）：

1. **不 fork 后端**：直接用 Aethersailor/SubConverter-Extended 官方镜像，跟随其 release；仓库零 subconverter/C++ 代码。
2. **零必填选项**：主路径 = 一个输入框 + 一个按钮，`target=auto`（UA 识别）为默认**便利**路径；折叠的「指定客户端」为**正式支持**路径（替同事/朋友生成特定类型订阅时用）；三档规则预设（默认 / 地区分组+AI 分流 / 全量+去广告）平台内置、随版本演进，暴露于高级折叠区（2026-10-24 修订：原「V1 先落一档、不暴露给用户」提前补齐为三档；主路径零选项不变）。
3. **单镜像一条命令（局域网开箱）**：单 image 内置前端静态页 + Extended 后端 + 内部反代（nginx）；V1 验收只覆盖局域网 HTTP 开箱；公网 HTTPS 不进 V1 架构，README 附录提供非官方 Caddy 反代示例（必须配合 token，见前提 6）。
4. **V1 输出标准 `/sub` 订阅链接**（默认 auto）；兼容范围按「已验证客户端 × 协议 × 模板」实测标注，不照抄 Sub-Store 清单，不承诺「同一链接总能返回正确格式」（UA 被改写/未知客户端/同名不同内核是已知限制）。**链接隐私属性（D6 定案）**：`/sub` 链接以 URL 编码内嵌朋友的订阅凭据——页面结果态与 README 明示「链接含订阅信息，仅自用勿转发」；nginx 对 `/sub`、`/api/*` 关闭 access_log（或 log_format 去掉 `$args`），sidecar 日志不记录订阅 URL；根治 = V2 短链（服务端映射，已在候选池）。
5. **规则新鲜度承诺降级为**「默认配置的远程规则自动更新」，逐客户端验证刷新路径（V1 验证范围 = Assignment 实测的两客户端，矩阵其余行标「未验证」）；降级行为选定：上游远端配置不可达时**不做本地兜底**（维持「不镜像不拷贝」），表现为客户端本次「更新订阅」失败或沿用其本地缓存（客户端行为），`/api/health` 徽章转 stale，README 说明；V2 候选「last-known-good 缓存」（若做需修订本条约束）。
6. **V1 只做剧本 A**：无账户、无订阅托管库、无「分享我的节点」。安全分档：局域网档默认无 token；公网档（附录路径）**强制**开启访问控制——token 由部署者经环境变量配置，**sidecar 在服务端把它注入生成的 /sub 链接**，朋友无感知、无需手动输入（页面不提供 token 的查看/输入入口；token 仅以不透明查询参数形式存在于生成的链接中——公网档下能打开页面的人即可取得带 token 链接属预期设计，token 防的是盲猜与 /sub 裸奔，不是页面访客）；/sub 不得在公网裸奔。

## Cross-Model Perspective

Codex（gpt-6.1-sol）冷读结论，已交叉比对并采纳：

- **最酷版本**：把「转换成功」推进到「朋友已经用上」——粘贴→生成→（对已验证客户端）导入交接→失败时展开指定客户端；成功指标定为「朋友无需问你，就完成首次导入」。不要假装浏览器知道用户装了哪个客户端。
- **识别的兴奋点**：「把自己的折腾成果变成朋友无需理解就能用的东西。」
- **50% 已有**：SubConverter-Extended（转换、UA 自动目标、远程资源、安全、多架构 Docker）；另 50% 是体验与集成工作：默认模板与客户端映射、导入交接、可理解的失败提示、兼容性验证、容器打包。
- **四条前提挑战（2 High / 2 Medium）**：UA 承诺过头、Sub-Store 矩阵不可直接继承、远程资源 ≠ 规则永远新鲜、单镜像是实现约束非需求本身——全部采纳为前提 2/4/5/3 的修订。

## Approaches Considered

- **A) 纯静态壳**（Effort S / Risk Low）：Vite+TS 静态页 + Extended 镜像 + nginx 两进程；客户端映射与预设全在前端常量；CI 监听上游 release 自动重发布。被否原因：状态徽章、V2 短链等服务端能力要二次架构。
- **B) 壳 + 薄胶水层**（Effort M / Risk Med）：同镜像内加极小 sidecar（Bun 或 Go 单二进制），`/api/health` 聚合版本与规则状态、`/api/clients` 出客户端注册表、错误文案翻译，为 V2 预留接口。**已选**。
- **C) 分叉改造 CareyWang 前端**（Effort M / Risk High）：fork 现成 Vue 表单前端删参数换皮。被否原因：Vue 2 + 老 webpack 工具链，「把表单删到一个框」是负功，背全部兼容包袱。

## Recommended Approach

**B：静态壳 + 薄 sidecar，单镜像三进程。** 用户为 V2 舒展度（短链、导入深链、状态徽章）主动选择超出最小方案的范围，接受 V1 期 sidecar 部分能力闲置。

架构：

```
┌──────────── 单镜像（amd64；arm64 待实证）────────────────────┐
│  s6-overlay（D2 定案）：监管下述三进程、崩溃重启              │
│  nginx（入口 + 静态托管 + 反代）                                │
│    /          → 前端静态页（Vite + TS）                        │
│    /api/*     → sidecar（Bun 或 Go 单二进制）                  │
│    /sub, /version, /healthz → SubConverter-Extended（上游镜像）│
└────────────────────────────────────────────────────────────────┘
```

- **前端**：Vite + TS 单页，三状态信息架构已由线框图钉死（见下）。
- **sidecar V1 职责**：
  - `/api/clients`：客户端注册表 + 预设模板（版本化的**远端配置 URL 映射**，非本地规则副本）
  - `/api/preview`：页面点「转换」后由前端调用；sidecar 以固定校验 UA 请求 `/sub`（用户指定 target 时用该 target；auto 时以 clash 作为校验探测格式），返回 `{ok, target, errorCode, message, link}`——**`link` 为服务端拼接的最终 `/sub` 链接（公网档在此注入 token）**，前端的复制按钮与二维码一律使用该字段，前端不自行拼接链接；**link 的 origin 推导规则**：取入站请求的 `Host` 头 + `X-Forwarded-Proto`（nginx 配置须显式 `proxy_set_header Host $host` 与 `X-Forwarded-Proto $scheme`，避免 sidecar 看到内部地址），并支持 `PUBLIC_BASE_URL` 环境变量覆盖（公网 Caddy 档使用）；README 两档部署文档同步说明该规则（实现期修正：`Host` 头透传用 nginx 的 `$http_host` 而非 `$host`，后者去端口会导致非 80 部署 link 丢端口——S2 冒烟实测发现，见 api-contract.md）；sidecar 维护错误码 → 人话映射表（如「这不像一个订阅链接——检查一下是不是复制全了？」），并须含前端侧 `api_unreachable`（/api/preview 本身失败：sidecar 宕机 / nginx 502 / 超时 →「服务暂时够不着，稍后再试」，与 Extended 错误码同级）；**超时边界**：sidecar→Extended 调用 10s、前端→/api/preview fetch 15s（超时按 api_unreachable 文案处理；数值 [estimated]，实现期可调）；**URL 预校验（D7）**：scheme ∈ {http, https} 且拒绝私网地址字面量（localhost / 127.0.0.0-8 / 10.0.0.0-8 / 172.16-31 / 192.168 / 169.254），不过返回专用错误码；README 同步披露 preview 为转发型抓取、公网档必须启用 token。页面状态②「转换中/出错」由此接口真实驱动；`ok:false` 时 `link` 照常返回（非 null），结果页仍展示链接并标注「未通过校验，仍可试用」，逃生口不变（D4 定案）
  - `/api/health`：契约 = `{backendVersion, presets: [{name, url, lastModifiedAt, lastSuccessAt, status}]}`（`lastModifiedAt` 取远端 Last-Modified，取不到为 null）；数据由 sidecar **周期自采**（每 15 min 抓各预设远端配置的 Last-Modified/ETag）；`status` 三态语义：fresh = 上次抓取成功**且内容** lastModifiedAt < 24h；stale = 上次抓取成功但内容 ≥ 24h 未变，**或**上次抓取失败；unknown = 从未成功。UI 文案 fresh/stale 显示「规则内容 X 前更新」、unknown 显示「规则库状态未知」；`backendVersion` 取自 `/version`（Extended README 快速开始节已列 /version 与 /healthz 为检查端点，Assignment 实证），取不到显示 unknown
  - token 注入（公网档开启时）：`/api/preview` 与生成链接由 sidecar 服务端注入部署级 token，朋友无感知
  - 预留 V2 短链/导入深链接口位
- **CI**：GitHub Actions 多架构构建；watch Extended 上游 release 自动 bump base image；**发布门禁 = 冒烟测试**（启动镜像，用 fixture 订阅分别转换 Clash 与 Surge，断言 HTTP 200 且输出格式合法；**第三步端到端**：调 `/api/preview` 取返回的 `link`，再分别以 Clash UA 与 Surge UA 通过 nginx 入口拉取该 link 并断言格式——证明「生成的链接可用」而不只是「/sub 能转」），不过不发布；tag 策略 = 不可变版本 tag（`vX.Y.Z`）+ 仅冒烟通过后移动的 `latest`，旧 tag 永久保留供回滚——「及时更新」从人工承诺变成带门禁的机器行为。

**线框图（已确认，布局即验收基准）**：`docs/wireframes/v1-three-states.png`（已入库；三状态文字描述见下作兜底）
三状态：① 初始（首屏唯一主角 = 输入框+按钮，高级区折叠退后，页脚状态灯）② 转换中/出错（按钮锁死；错误文案说人话+指下一步，由 `/api/preview` 真实驱动；客户端 chips 展开态，「自动识别 ✓」默认选中）③ 结果（复制按钮 + 二维码 + 「链接是活的」说明）。**文案修订**：结果态不写「已按你的 App 自动出对应格式」——auto 的格式在**客户端拉取 /sub 时**才由 UA 决定，页面运行在浏览器里无从得知 App；改为「导入你的 App 时会自动适配格式」，「？我是 Clash 用户」= 一键锁定 `target=clash` 重新生成链接的逃生口；线框图中 `https://sub.你的域名.com` 仅为示意，V1 实际输出 `http://<部署机地址>`；结果态复制按钮旁加一行小字「链接含订阅信息，仅自用勿转发」（D6）。

风格方向：实现阶段用 /design-consultation 专项定调；基调 = Linear/Vercel 级干净但更暖、中文优先、浅色为主可暗色。

## Success Criteria

- **部署**：全新 Linux 机器一条 `docker run` 起服务（局域网 HTTP，公网不在 V1 验收范围）；Docker Hub + GHCR 双源；amd64 必须提供；arm64 以上游 manifest 实证为准（见 Dependencies），未实证前不承诺
- **朋友闭环**（核心指标，codex 版）：两个真实客户端（一 iOS 一 Android）完成「粘贴→导入→再次更新」，全程不问部署者
- **兜底路径**：手动指定客户端后，对应客户端导入成功
- **错误路径**：状态②「转换中/出错」由 `/api/preview` 真实驱动（错误来自 Extended 实际错误码的翻译映射），错误文案零术语
- **规则新鲜度**：默认配置下，客户端「更新订阅」能拉到上游最新规则（抽一条规则验证）；模拟上游不可达（改错 URL）时徽章转 stale。**新鲜度主张 = 徽章语义**（远端 Last-Modified/ETag 所述的内容最后修改时间；头缺失/不可信时为 unknown，不冒充 fresh）——不是绝对断言，README 对外文案与此一致
- **页面**：首屏一眼只有输入框+按钮（对齐线框图状态①）；复制/二维码输出的链接在局域网 IP 直连下实测可用（origin 推导正确）

## Distribution Plan

- Docker Hub + GHCR 双源镜像，tag 策略 = 不可变版本 tag + 冒烟通过后移动的 `latest`（见 CI）
- README 部署文档：局域网开箱（V1 官方路径，默认；写明端口绑定范围警告——公网 IP 主机必须走附录）/ 公网附录（非官方 Caddy 反代示例 + **强制 token**，/sub 不得裸奔）；**链接属性三披露**：凭据内嵌仅自用（D6）、preview 为转发型抓取公网档必须 token（D7）、生命周期与 token 轮换爆破半径 + 泄露应对（D8）
